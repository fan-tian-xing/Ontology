# 可控难度与组合任务自动生成：TaskCraft 论文调研及研究思路

## 1. 研究目标与论文定位

本研究需要自动生成既能检验经验迁移，又能检验多段经验组合的新任务。TaskCraft 的价值在于提供明确的任务结构操作：从工具相关的原子任务开始，通过深度扩展增加依赖链，通过宽度扩展组合子问题。它主要研究任务与训练数据生成，并没有直接完成“历史经历→新任务”的受控经验迁移评测。

## 2. 论文动机：能出题，不等于能出需要工具的 Agent 任务

现有高质量 Agent Benchmark 人工成本较高，规模难扩大；普通指令合成方法则容易生成模型依靠已有知识就能回答的问题，缺乏真实工具交互。

作者希望自动生成三种性质兼具的数据：必须调用外部工具、复杂度能逐步扩展、题目和答案有可追踪依据。另一个目标是避免每次加难后都重新执行整道复杂任务，使生成成本随难度上升得过快。[依据：原文 Introduction、Automated Task Generation Workflow]

## 3. 方法一：从工具上下文反向构造原子任务

### 3.1 单个工具任务怎样表示

作者用以下关系组织原子任务：

- 工具 T 接收输入索引 iT，例如文档名称、网页标题或图像路径；
- 工具执行后返回上下文 C；
- 从 C 选取答案 a，并提炼题目需要的关系 R；
- 据此生成问题 q，使求解者需要定位 iT、调用工具并运用 R 得到 a。

因此，生成器不是只看一个答案自由编题，而是同时利用“从哪里取得证据”和“怎样由证据得出答案”。[依据：arXiv v2 §2、§3.1]

### 3.2 原子任务如何筛选

对候选题分别运行可用工具的 Agent 与不调用工具的推理 LLM，再由判断模型对照标准答案，优先保留工具 Agent 能答对而无工具模型不能答对的题。

原子任务在概念上对应一次目标工具调用，但验证实际允许有限多步，例如三步。因此，不能宣称每个保留任务都被严格证明只需一次调用；无工具模型失败也只是相对所用模型与预算的工具必要性证据。[依据：arXiv v2 §3.3；后半为本笔记解读]

## 4. 方法二：用深度与宽度控制任务结构

### 4.1 深度扩展：把已知检索入口变成待解决的子问题

假设原题能在“文档 X”中找到答案。深度扩展先构造一个能够找出 X 的新子问题，再以该子问题替换题目里原本直接给出的 X。新的求解过程就需要先识别入口，再完成原问题。

这个过程中，原题答案可保持不变，但入口识别多出一层依赖；多次递归后形成工具调用依赖链。[依据：arXiv v2 §3.2]

**便于理解的自拟例子，并非论文原例：**

原题为“查报告 X 的某指标”；扩展后变为“先根据发行机构、年份与主题找到报告，再查同一指标”。若扩展后的描述仍直接暴露 X，或能绕过新子问题取得答案，就没有真正增加依赖。

### 4.2 宽度扩展：把多个任务合成需要分解的问题

宽度扩展把多个子问题及其答案合并、重写，让求解者分别获得分支结果后完成最终输出。它控制的是并行分支与子问题数量；深度扩展控制的是串行依赖。

对本课题而言，宽度扩展是生成组合候选的起点，但将两个问题并排，尚不足以证明模型会融合经验。可以进一步让一个分支的输出成为另一个分支的约束，或要求对两个分支结果进行统一决策。[前半依据：arXiv v2 §3.2；后半为课题建议]

### 4.3 轨迹从哪里来

简单任务可由 Agent 直接执行并记录工具选择、参数、返回结果和计划；复杂题在逐步扩展与验证时保留各增量部分及其依赖，再形成参考求解过程。正式版还使用 Oagents 采样训练轨迹并转换为工具整合推理格式。

构建时可追踪的参考过程，与某个独立 Agent 从最终题面完整解出的轨迹应区分记录，不能默认二者相同。[依据：arXiv v2 §3.2；正式版 §4.3；最后一句为评测建议]

## 5. 方法三：增量验证与防止伪扩展

### 5.1 为什么验证不需要每次重解全题

原子任务已经执行验证；扩展时重点验证新增加的关系、入口替换和最终题面逻辑。深度扩展主要依赖 LLM 的语言与关系分析，不要求 Agent 每轮从头完成全部新任务。[依据：arXiv v2 §3.3、附录 B]

### 5.2 重点拦截两类问题

1. **伪扩展：** 看似增加一个子问题，实际形成循环、等价改写，或者没有新增有效依赖。
2. **信息泄漏：** 新题保留了本应由中间步骤求出的入口、答案线索，导致无需经历新增步骤。

判断器检查新增关系是否合理、原索引是否正确替换，并用无工具推理检查是否容易直接得出答案。

这种验证提高效率，但属于模型审核，并非形式化证明，也不等于把每一道最终题都独立重放验证。若将它用于本研究的正式测试集，建议另加端到端执行、独立求解与抽样人工审核。[依据：arXiv v2 §3.3、附录 B；末段为证据边界与建议]

### 5.3 总体流程

~~~mermaid
flowchart LR
    A[网页 PDF 图像等语料] --> B[工具取得上下文]
    B --> C[反向生成原子任务]
    C --> D[有工具与无工具对照筛选]
    D --> E[深度依赖扩展或宽度组合]
    E --> F[新增关系与泄漏检查]
    F --> G[保留任务 答案 过程依赖]
    G --> H[采样轨迹并进行 SFT 或 RL]
~~~

## 6. 实验怎么验证方法有效

### 6.1 生成效率：经验样例能否帮助生成流程

正式版表 2 比较 bootstrap few-shot 提示优化前后：

| 生成阶段 | 原通过率 | 优化后通过率 | 原耗时 | 优化后耗时 |
| --- | ---: | ---: | ---: | ---: |
| 原子任务生成 | 54.9% | 68.1% | 29.1 秒 | 23.5 秒 |
| 深度扩展，六次尝试口径 | 41.0% | 51.2% | 31.5 秒 | 30.2 秒 |

该实验支持生成流程可以借助优质样例提高通过率和效率；它评测的是生成器提示优化，不是新任务求解中的经验迁移。[依据：正式版 §4.2、表 2]

### 6.2 下游训练：同规模数据是否优于常规多跳 QA

正式版 §4.3 使用不同底座，在 GAIA、WebWalker、论文表头写作 BrowserComp 的检索基准、HLE 上评估。BrowserComp 对应引用中的 BrowseComp，本笔记保留正式表头标注，避免把它误认为另一项新基准。

Qwen-2.5-7B-Instruct 上，均仅 SFT，正式版表 3 节选如下：

| 训练数据 | GAIA | WebWalker | BrowserComp（原表头） | HLE |
| --- | ---: | ---: | ---: | ---: |
| 7.5k MHQA | 20.4 | 23.4 | 3.6 | 4.2 |
| 7.5k TaskCraft | 36.3 | 55.0 | 12.4 | 16.4 |
| 5k MHQA＋2.5k TaskCraft | 34.0 | 52.6 | 6.4 | 13.2 |

同样数量的训练任务下，TaskCraft 数据带来更高结果，减弱了“只是多给了训练样本”这一解释。任务数相同并不自动等于训练 token 或总计算量完全一致，仍需区分控制口径。[依据：正式版 §4.3、表 3；末句为本笔记分析]

### 6.3 RL 与数据规模扩展

在 Qwen-2.5-32B-Instruct 上，以 5k MHQA＋2.5k TaskCraft 做 SFT 后，GAIA 为 **60.2**，原表 BrowserComp 为 **21.0**；继续使用 8k TaskCraft 任务做 RL 后分别为 **60.8** 和 **24.8**。这是更大训练流程的效果，不是纯粹只替换生成器某个模块的消融。[依据：正式版表 3]

正式版表 5 还固定 Qwen2.5-7B-Instruct 的训练设置，使用不同规模 TaskCraft 数据：

| 训练任务数 | GAIA-103 Pass@3 |
| --- | ---: |
| 1,000 | 17.5% |
| 3,000 | 31.1% |
| 5,000 | 39.8% |

这支持该设置中的训练数据扩展收益。Pass@3 不能与其他表格的单次成功率直接比较，也不能用这条训练曲线反驳 [[EmbodiedCLBench]] 的测试时经验数量曲线：二者改变的变量和学习机制不同。[依据：正式版表 5；比较边界为本笔记分析]

### 6.4 工具上下文消融与证据范围

arXiv v2 表 4 中，去掉输入索引和关系、直接提示 LLM 生成原子题，通过率为 **18.5%**；结构化生成为 **43.0%**，工具调用次数方差从 **1.2** 降至 **0.4**。这支持显式工具上下文有助于生成质量及复杂度稳定性。

原文关于耗时减少的文字与表格算术有不一致：119.7 秒减 86.7 秒为 33.0 秒，因此本笔记不沿用文字中的“28 秒”。该项仅按 arXiv v2 标注，不能与正式版 41k 规模混成同一版本实验。[依据：arXiv v2 §4.5、表 4]

## 7. 对经验迁移与组合 Benchmark 的借鉴

以下是本课题可实施的改造方向，并非 TaskCraft 原文已验证的结论。

### 7.1 从单题扩展改成“历史任务族—新组合任务”

保留原子任务及每次扩展的来源关系，先让 Agent 实际执行基础任务，再生成结构发生变化的新目标：

- **深度轴：** 历史操作相同，新任务增加中间识别与数据依赖；
- **宽度轴：** 不同历史经历提供互补程序，新任务需要多个分支协作；
- **条件轴：** 相同程序换对象、资源约束或工具环境；
- **干扰轴：** 插入表面相似但操作不适用的历史经历。

### 7.2 显式记录需要组合哪几段历史

每个候选新任务保留依赖图，并将依赖节点映射到历史经验来源。对 A+B 组合，至少运行无经验、A、B、A+B 和无关经验五类条件，必要时加入直接给出关键程序的诊断参考。

生成器知道的参考答案、目标任务完整解法不能进入历史经验。优先使用程序、触发条件和边界作为迁移内容，降低直接搬运同一答案的风险。

### 7.3 防止“题变长”代替“组合能力变强”

增加题面长度、工具次数或分支数量，只说明结构更复杂。要解释组合能力，应同时观察：各段经验是否被正确选出、是否被读取、子任务接口是否匹配，以及移除某段后是否丢失必要支持。最终成功率与这些过程指标需共同报告。
