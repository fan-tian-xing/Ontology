# 经验组合与持续学习评测：EmbodiedCLBench 论文调研及研究思路

## 1. 研究目标与论文定位

本研究希望测试：Agent 能否把多段历史执行经历组合起来，解决从未执行过的新任务。EmbodiedCLBench 把这一问题落实为“先完成基础家务任务，再解决由基础技能组合而成的高级任务”，与经验组合评测直接相关。

### 1.1 论文全名、发表信息与阅读版本

- **英文全名：** *EmbodiedCLBench: Evaluating Continual Learning for Self-Evolving Embodied Agents*。
- **中文释义：** EmbodiedCLBench：评测自我演化具身智能体的持续学习能力。
- **作者：** Jie Huang、Yanan Chen、Ruixun Liu 等。
- **年份与状态：** 2026 年 arXiv 预印本；首次提交于 2026 年 10 月 9 日。截至本次核对，所查原文、项目页和官方仓库未提供可确认的正式期刊或会议发表信息，不能将 arXiv 当作期刊。
- **标识：** arXiv:2610.13021，DOI 为 10.48550/arXiv.2610.13021。
- **阅读版本：** arXiv v1；核对日期 2026-11-20。

信息见 [arXiv 官方条目](https://arxiv.org/abs/2610.13021)与[作者项目页](https://pku-value-lab.github.io/EmbodiedCLBench-homepage/)。

## 2. 论文动机：用组合泛化把“从经验中学习”变成可测问题

持续学习要求积累过去经验并用于未来任务。但常见具身评测主要测感知、导航、操作和规划，没有明确安排“先经历什么、再测试什么”。独立完成一道复杂任务，也无法说明 Agent 是否利用了历史技能。

作者因此用 compositional generalization（组合泛化）操作化持续学习：先执行较简单任务，保留经历或提炼技能，再尝试一个未见的复杂组合。这里主要研究测试时利用上下文与外部技能总结，不能理解为通过本基准更新模型权重后再测试。[依据：原文 §1–§3]

## 3. 方法一：原子动作—基础任务—高级任务

### 3.1 三层任务结构

| 层级 | 含义 | 与经验评测的关系 |
| --- | --- | --- |
| 原子动作 | 一个对象交互单元，可能需要若干执行步骤 | 组成技能的底层单元 |
| 基础任务 | 组合少量原子动作的家务活动 | 在学习阶段提供经历 |
| 高级任务 | 重组多个基础任务类别中的动作 | 在测试阶段检验组合泛化 |

原文中的“pick up the cup”这一原子动作，仍可能包含走近、看向、拿取三个执行步骤。因此，不能把论文的 atomic action 数量直接当成 API 调用步数。

主基准包含 **168 个基础任务和 100 个高级任务**，共 268 个。基础任务覆盖六类家务；主设置中基础任务为两个原子动作、最短六步，高级任务为四个原子动作、最短十二步，高级任务的动作来源涉及两至四个基础任务类别。[依据：原文 §3.2、§4.1、图 3]

### 3.2 任务怎么产生，是否全自动

作者使用 TongSim 家庭环境，基于可交互对象和动作构建任务。任务描述由 Qwen3.7-Plus 生成并人工核验。该方法包含模型辅助生成和人工质量检查，不能描述为无需人工的完整自动构建流程。[依据：原文 §3.1–§3.3]

## 4. 方法二：将具身任务转成可复现的离线状态图

### 4.1 为什么不用在线模拟器直接评测

作者采用的 TongSim 闭源版本支持更丰富动作，但不适合直接开放在线评测，因此将任务预先构建为状态转移图。

每个节点保存当前状态、第一视角图像和候选动作；可执行动作形成确定性转移边。Agent 每轮观察图像、选择候选动作，再进入下一节点，直到达到目标或耗尽步数。[依据：原文 §3.3–§3.4]

### 4.2 怎样区分好动作与错误动作

作者为任务指定起点与目标，用广度优先搜索寻找最短路径，再围绕路径扩展可执行的干扰分支。候选动作分为：

1. **最优动作：** 沿最短路径前进；
2. **次优动作：** 当前能执行，但偏离最短路径；
3. **无效动作：** 当前状态下不能执行。

图像、动作候选及其关系经生成与人工检查。该设计支持细粒度行为分析，但评测的是限定图空间中的视觉决策与规划，不包含开放世界任意动作生成或完整机器人连续控制。[依据：原文 §3.3–§3.4；最后一句为评测范围解读]

### 4.3 总体流程

~~~mermaid
flowchart LR
    A[TongSim 对象与动作] --> B[生成并审核基础与高级任务]
    B --> C[构建离线状态图]
    C --> D[Agent 执行相关基础任务]
    D --> E[保留轨迹或总结技能]
    E --> F[执行未见高级任务]
    F --> G[完成率与动作类型分析]
~~~

## 5. 评测协议：同一新任务，比较三种经验条件

| 设置 | 学习阶段 | 测试阶段可见内容 |
| --- | --- | --- |
| Zero-shot | 无 | 高级任务与当前状态 |
| In-Context Learning，ICL | 执行两个相关基础任务 | 完整基础任务交互轨迹 |
| Skill Learning | 执行同样两个基础任务，再写 Markdown 总结 | 技能总结，不提供完整历史轨迹 |

主设置中，测试任务预算为最短路径加三步，学习阶段为最短路径加六步。技能总结与原始轨迹形成两种经验表达方式；论文主协议未把自动从大型经验库检索作为独立变量。[依据：原文 §3.4、§4.1]

## 6. 实验怎么验证经验组合评测有效

### 6.1 实验配置与主指标

实验使用 Hermes、OpenClaw、Codex、Claude Code 四种 Agent 框架，分别搭配论文所列的 Qwen3.8-Flash、GPT5.6-Terra。主指标为限定步数内达到目标的 Success Rate（SR）。

这些模型名称按原文记录；不是本笔记对当前模型产品命名的补充判断。[依据：原文 §4.1]

### 6.2 主实验：先经历基础任务是否有帮助

下表节选原文表 1，均为高级任务成功率：

| 框架与底座 | 无经验 | 完整轨迹 ICL | 技能总结 |
| --- | ---: | ---: | ---: |
| Hermes / Qwen3.8-Flash | 8.0% | 44.0% | 33.0% |
| OpenClaw / Qwen3.8-Flash | 5.0% | 35.0% | 38.0% |
| Codex / GPT5.6-Terra | 11.0% | 52.0% | 26.0% |
| Claude Code / GPT5.6-Terra | 9.0% | 31.0% | 25.0% |

完整轨迹和技能总结均可明显优于无经验，但不存在一种表达方式始终胜出。例如 Codex / GPT5.6-Terra 的完整轨迹条件比无经验高 41 个百分点；OpenClaw / Qwen3.8-Flash 则是技能总结略高于完整轨迹。[依据：原文 §4.2、表 1]

这验证了基础经历对未见高级任务有帮助，但尚不能仅凭主表断定增益全部来自“多段技能的必要组合”：经历中还可能包含通用动作有效性知识或对环境规则的熟悉。需要更严格的单段、无关经验与逐段移除对照来区分。[本笔记的证据边界分析]

### 6.3 改变组合复杂度：任务更难时经验是否仍有价值

作者把高级任务从三个原子动作扩展至六个，在 Hermes / Qwen3.8-Flash 上比较。六动作时，无经验为 **4.0%**，ICL 为 **32.0%**，技能总结为 **26.0%**。

绝对成功率随组合复杂度增加而下降，但经验相对无经验仍有收益。因此更准确的表述是“该设置下经验收益在更复杂任务上仍然存在”，不能扩展成持续学习与所有形式的任务难度无关。[依据：原文 §5.1、图 4]

### 6.4 增加经验数量：有经验有效，不等于经验越多越好

作者将学习任务数量从零增加至六，使用 Hermes 和 OpenClaw，底座均为 Qwen3.8-Flash。最大跃升发生在零条到一条经历：成功率从约 8%–10% 提高到约 28%–40%。继续加入经历后，四条曲线均没有稳定上升趋势。

这揭示了当前方法积累更多经验的局限。但实验中新增经历的独特信息量、冗余程度也可能影响曲线，不能据此断言所有新增经验均无价值。[依据：原文 §5.2、图 5；解释边界为本笔记分析]

### 6.5 过程与预算分析

原文 §5.3 用主实验的动作记录分析经验如何改变决策：无效动作选择率下降，最优动作选择率上升，次优但可执行动作也略有增加。这说明部分收益可能来自更少选择不可执行动作，而不只是整体规划质量提高。

§5.4 将额外步数从零变到六；在该敏感性实验中，经验组保持优势。预算最严格、没有额外步数时，Zero-shot 为 0%，ICL 为 15%，技能总结为 7%。这降低了“经验收益只是多给容错预算”的解释空间，但该结论仍限定于所测配置。

## 7. 对本研究的借鉴与改造

以下为本课题建议，不是原文已完成的协议。

### 7.1 保留“基础经历—未见组合”的对应关系

每道高级任务明确记录所需技能，以及这些技能分别来自哪些历史任务。再添加三类测试：

- **同技能新对象：** 操作方式相同，实体发生变化；
- **新条件迁移：** 目标相同，但起始状态或约束改变；
- **新结构组合：** 历史技能分别出现过，但新的依赖顺序和组合未出现过。

这样能把泛化变化与一般任务难度分开。

### 7.2 验证组合是否真的必要

对需要技能 A、B 的新任务，比较无经验、仅 A、仅 B、A+B、同长度无关经验。在 A+B 组里再逐段移除，检查收益是否依赖互补经历。目标任务应包含跨子任务的数据依赖或状态依赖，不能只是把两个独立小题并排。

如果一条基础经历已经带来几乎全部增益，应该进一步检查它是否只教会了通用界面规则；这与“能否融合多段互补经验”是不同问题。

### 7.3 增加记忆规模与干扰维度

把相关经验数、总经验库大小、冗余度、冲突比例分别控制。更多经历不必然表示更多相关信息；只有把这些变量拆开，才能解释经验规模曲线。

主结果同时报告 SR、相对无经验提升、动作无效率、超出最短路径的步数，以及经验来源覆盖率。对于长时间持续学习，还需加入旧任务复测，区分新任务迁移和旧技能遗忘。
