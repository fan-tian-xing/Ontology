[[TRACE]]：由已有benchmark，依靠提议器对轨迹中的难点等分析，提出可以演化的新方向，执行器沿着新方向执行，得到一条轨迹，并由轨迹逆向得到任务题目，最后验证器验证问题是否正确。
[[EvoAgentBench]]：对已有benchmark的执行轨迹进行提炼，得到Ability 卡片，合并相同能力，这样可以建立ability图，节点为任务，如果两个任务共用一个能力卡片就建立边。最后划分训练集和评测集，使得评测集的任务至少存在一项有历史支持的可迁移能力，同时保持任务实例不重合。
实验设计多组，无经验，agent自己构建经验和利用经验（各种方法），以及由基准方整理并定向提供相关技能，用于评估经验迁移收益。
[[TaskCraft]]：从网页、PDF、图像等材料出发，先调用工具获取内容，从中选择答案，再反向生成基本的“原子任务”。比较有工具 Agent 与无工具模型的回答，保留工具侧表现更好的题。随后通过深度扩展，把原本直接给出的材料入口变成需要先解决的子问题；通过宽度扩展，将多个子问题合成一道任务。扩展时主要检查新增关系是否成立、题目是否泄漏答案或存在捷径，并保留答案依据和参考求解过程。  
[[AutoPlay]]：从可交互的应用环境出发，让探索 Agent 多轮操作，记录截图、动作，并总结已探索内容，帮助后续探索发现新的功能和状态。任务生成器以探索轨迹作为环境背景，结合功能使用、信息检索、功能组合等出题指南，生成有实际环境依据的任务。随后由执行器尝试完成任务，验证器根据执行轨迹判断是否成功，筛选出成功示范。
