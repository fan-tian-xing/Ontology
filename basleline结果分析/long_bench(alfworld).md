# ALFWorld：no-exp 与 Self-Refine 结果分析

## 1. 整体结果与增益拆分

![](assets/long_bench(alfworld)/alfworld_accuracy.png)

| 划分     | no-exp | Self-Refine 首轮 | Self-Refine 最终 |
| ------ | -----: | -------------: | -------------: |
| seen   | 79.29% |         78.57% |         86.67% |
| unseen | 76.87% |         80.35% |         87.31% |

与独立 no-exp 相比，Self-Refine 的最终成功数在 seen 上由 **333/420 增至 364/420**，在 unseen 上由 **309/402 增至 351/402**。

## 2. 两种方法如何利用经验？

| 项目 | no-exp | 此处的 Self-Refine |
| -------- | -------------------- | ---------------------- |
| 执行机会 | 一轮，最多 50 个环境动作 | 重置同一任务后再执行一轮，每轮最多 50 个环境动作 |
| 输入信息 | 任务、当前观测、合法动作列表、当前轮历史 | 在左侧信息基础上，加入完整首轮“实际动作—后续观测”轨迹 |
| 首轮成功后的处理 | 结束 | 仍重新执行第二轮 |
| 成功率 | 单轮环境结果 | **只记第二轮结果** |
| Token | 单轮全部请求 | **两轮全部请求相加** |

两种方法的首轮提示词模板和请求参数相同。按任务和运行编号对齐后，共有 822 对首次请求，两组的提示词和初始环境均一致，但模型返回的文本仍可能不同，因此首轮成功率也存在差异。

Self-Refine 利用的是**当前任务自身的执行经验**：既复用成功路径，也利用失败观测调整后续操作。它不检索跨任务经验，也不向模型提供专家计划；传入第二轮的轨迹不包含首轮模型的推理文本、显式奖励或官方得分。与 AIME 的实现不同，这里没有单独输出 `Verdict` 的反馈轮，而是在重新执行任务的每一步结合首轮轨迹进行反思。

## 3. 第二轮具体改善了什么？

下表中的“救回/丢失”分别指“首轮失败、第二轮成功”和“首轮成功、第二轮失败”的运行记录数。

| 任务类型 | seen：首轮→第二轮成功率 | 救回/丢失 | unseen：首轮→第二轮成功率 | 救回/丢失 |
| --- | --- | ---: | --- | ---: |
| 灯下观察 | 84.62% → 87.18% | 2/1 | 87.04% → 98.15% | 6/0 |
| 简单取放 | 97.14% → 100.00% | 3/0 | 100.00% → 100.00% | 0/0 |
| 清洗后放置 | 76.54% → 86.42% | 8/0 | 77.42% → 81.72% | 4/0 |
| 冷却后放置 | 64.00% → 84.00% | 15/0 | 77.78% → 90.48% | 8/0 |
| 加热后放置 | 29.17% → 43.75% | 7/0 | 46.38% → 60.87% | 11/1 |
| 放置两个物体 | 98.61% → 98.61% | 0/0 | 100.00% → 100.00% | 0/0 |

原始轨迹中的代表案例：

| 案例                                         | 首轮失败过程                                             | 第二轮实际改变                                                           |
| ------------------------------------------ | -------------------------------------------------- | ----------------------------------------------------------------- |
| seen / run_01 / WineBottle→Shelf，0048      | 搜索柜子、抽屉等，直到第 50 步才在 `diningtable 1` 发现酒瓶，此时行动预算已耗尽 | 首步直接前往 `diningtable 1`，取瓶后前往 `shelf 1` 放置；**4 步成功**               |
| unseen / run_03 / Egg 加热后放 GarbageCan，0106 | 已找到鸡蛋，但反复开关、检查微波炉，始终未执行有效的加热动作，50 步后仍未完成任务         | 定位鸡蛋后执行 `heat egg 1 with microwave 1`，再放入垃圾桶；**6 步成功**            |
| unseen / run_03 / Pan 清洗后放 CounterTop，0060 | 先误拿 `pot`，之后才找到目标 `pan`；把 `pan` 放到水槽后清洗失败，又反复取放    | 直接取 `pan`，保持手持状态执行 `clean pan 1 with sinkbasin 1`，再放到台面；**6 步成功** |

这些案例体现了 Self-Refine **复用物体位置信息、跳过无效探索、修正目标识别和动作前提**的作用。模型利用首轮搜索结果和失败反馈，形成了更短的执行路径。

第二轮也可能退化：seen 的一条灯下观察任务首轮用 32 步成功，第二轮却在 50 步内未完成。模型将首轮已成功的轨迹误解为失败，再次反复取放 `keychain`。unseen 另有一条加热任务也由成功变为失败。由于首轮成功后仍会重新执行第二轮，这类退化会影响最终成功率。
