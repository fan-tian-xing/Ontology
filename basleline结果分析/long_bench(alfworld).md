# ALFWorld：no-exp 与 Self-Refine 结果分析

> Qwen3.5-27B，关闭 thinking。seen 140 任务 × 3 次，unseen 134 任务 × 3 次。以下差值均为百分点。
> **核对结论：截图四行的成功率和输入、输出 Token 均正确。** 新提供的根目录 no_exp、self_refine 中，12 次运行文件齐全，无缺失或零字节轨迹。已逐轮核对 2,466 次环境执行、48,283 次模型调用、101,498 条日志：动作解析、观测链、环境 won、样本、官方结果、汇总均一致。数据版本与评估代码也一致。核查日期：2026-11-12。

## 2. 两种方法如何利用经验？

| 项目 | no-exp | 此处的 Self-Refine |
|---|---|---|
| 执行机会 | 一轮，最多 50 个环境动作 | 同任务重置后再执行一轮，每轮最多 50 动作 |
| 输入信息 | 任务、当前观测、合法动作列表、当前轮历史 | 加入完整首轮“实际动作—后续观测”轨迹 |
| 首轮成功后的处理 | 结束 | 仍重新执行第二轮 |
| 成功率 | 单轮环境结果 | **只记第二轮结果，不取两轮最大值** |
| Token | 单轮全部请求 | **两轮全部请求相加** |

两种方法首轮模板和请求参数相同；822 对同题同运行编号的首次请求，其提示词和初始环境完全一致，但返回文本可能不同，因此首轮结果仍有差异。

Self-Refine 利用的是**当前任务自身的执行经验**：既复用成功路径，也利用失败观测调整后续操作。它不检索跨任务经验，不提供专家计划；传入第二轮的轨迹也不含首轮模型推理文本、显式奖励或官方得分。与 AIME 实现不同，这里没有单独的 Verdict 反馈轮，而是在重做任务的每一步结合旧轨迹反思。

## 3. 第二轮具体改善了什么？

| 任务类型 | seen：首轮→第二轮 | 救回/丢失 | unseen：首轮→第二轮 | 救回/丢失 |
|---|---|---:|---|---:|
| 灯下观察 | 84.62% → 87.18% | 2/1 | 87.04% → 98.15% | 6/0 |
| 简单取放 | 97.14% → 100.00% | 3/0 | 100.00% → 100.00% | 0/0 |
| 清洗后放置 | 76.54% → 86.42% | 8/0 | 77.42% → 81.72% | 4/0 |
| 冷却后放置 | 64.00% → 84.00% | 15/0 | 77.78% → 90.48% | 8/0 |
| 加热后放置 | 29.17% → 43.75% | 7/0 | 46.38% → 60.87% | 11/1 |
| 放置两个物体 | 98.61% → 98.61% | 0/0 | 100.00% → 100.00% | 0/0 |

**冷却、加热任务贡献了 41/64 条救回记录。** 简单取放和双物体放置本来已接近满分，额外提升空间较小；需要处理物体状态、操作顺序的任务更受益。

原始轨迹中的代表案例：

| 案例 | 首轮失败过程 | 第二轮实际改变 |
|---|---|---|
| seen / run_01 / WineBottle→Shelf，0048 | 搜索柜子、抽屉等，直到第 50 步才在 diningtable 1 发现酒瓶，预算耗尽 | 首步直接去 diningtable 1，取瓶、去 shelf 1、放置；**4 步成功** |
| unseen / run_03 / Egg 加热后放 GarbageCan，0106 | 已找到鸡蛋，但反复开关、检查微波炉，没有有效加热，50 步失败 | 定位鸡蛋后执行 heat egg 1 with microwave 1，再放入垃圾桶；**6 步成功** |
| unseen / run_03 / Pan 清洗后放 CounterTop，0060 | 先误拿 pot，后找到 pan；把 pan 放到水槽后清洗失败，又反复取放 | 直接取 pan，保持手持状态执行 clean pan 1 with sinkbasin 1，再放到台面；**6 步成功** |

这些案例分别体现了**复用物体位置、跳过无效探索、修正目标识别和动作前提**。它把首轮零散的搜索和失败反馈转成更短的执行路径。

第二轮并非总能改好：seen 一条灯下观察任务由 32 步成功变成 50 步失败；模型把原本已成功的轨迹误解为失败，又反复取放 keychain。unseen 另有一条加热任务由成功变失败。由于首轮成功也强制重做，存在这类退化风险。

## 4. 成功率提高伴随什么成本？

![](assets/long_bench(alfworld)/alfworld_tokens.png)

| 划分 | 方法 | 平均输入 Token | 平均输出 Token |
|---|---|---:|---:|
| seen | no-exp | 26708.61 | 14517.06 |
| seen | Self-Refine | 64005.68 | 26797.10 |
| unseen | no-exp | 26701.14 | 22307.31 |
| unseen | Self-Refine | 62549.96 | 34703.28 |

相对 no-exp，Self-Refine 的输入/输出总量分别为：seen **2.20 倍**，unseen **1.98 倍**。这些消耗已包含首轮和第二轮，不能只计修正阶段。

| 划分 | 首轮平均动作数 | 第二轮平均动作数 | 首轮平均输入 Token | 第二轮平均输入 Token |
|---|---:|---:|---:|---:|
| seen | 22.89 | 12.72 | 27,415 | 36,590 |
| unseen | 22.62 | 13.33 | 25,662 | 36,888 |

第二轮动作数减少约 **44% / 41%**，但输入仍更多，因为每一步都会再次带入完整首轮轨迹。输出总量则低于首轮，符合执行路径缩短的观察。

整体改善不能归结为“格式更稳定”：第二轮的格式失败率 seen 为 **6.22%**，高于首轮 **3.36%**；unseen 为 **5.95%**，与首轮 **5.80%** 接近。部分案例减少了乱码和无效动作，但总体优势更清楚地体现在路径规划和操作顺序。

## 5. 如何解释这次提高？

**结果确有日志支持，作用机制也能在轨迹中观察到；但比较同时增加了执行机会和同任务信息。** no-exp 只尝试一次，Self-Refine 最多使用两轮共 100 个动作，并提前看到首轮探索结果。若要单独测量“反思”贡献，需要再加“重置后第二次执行，但不提供首轮轨迹”的对照，或让方法共享同一批初答。

还需注意官方环境的抽象：有一条 Mug 冷却任务在 cool 动作后直接 won，未再执行最终放置。检查该游戏 PDDL，发现同一 mug 初始同时带有台面和咖啡机两处容器归属；从台面取走后，另一归属仍在，冷却即可满足官方目标。此类结果应按官方游戏状态解释，不能仅凭自然语言直觉判错；目前没有量化它对整体增益的影响。

报告使用的是根目录 no_exp、self_refine 的离线日志核对，没有重新运行 PDDL 引擎。任务重复三次仍是同一批游戏，图表仅展示描述性结果，不宣称统计显著性。
