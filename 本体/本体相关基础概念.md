# RDF / RDFS / OWL 本体零基础概念


本文示例中的 `uni:`、`rdf:`、`rdfs:`、`owl:` 等都是长 IRI 的缩写。每段代码不再重复写完整声明，常用前缀统一如下：

阅读时要一直区分三个层次：现实中的事物、本体要表达的含义，以及本体文件中使用的符号。例如，现实中的小明不是 `uni:Xiaoming` 这串字符；`uni:Xiaoming` 是知识系统中用来指代小明的 IRI。

```turtle
@prefix uni: <https://example.org/university/> .
@prefix person: <https://example.org/person/> .
@prefix external: <https://external.example.org/resource/> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
```

## 一、先看一个完整例子

现实中有一个叫“小明”的学生，他在清华大学学习人工智能课程。我们可以把它写成下面几条知识：

1. 小明是一名学生。
2. 每个学生都是人。
3. 小明就读于清华大学。
4. 小明选修了人工智能课程。
5. 小明的中文姓名是“小明”。

使用 RDF 的 Turtle 写法表示如下：

```turtle
@prefix uni: <https://example.org/university/> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .

uni:Xiaoming rdf:type uni:Student .
uni:Student rdfs:subClassOf uni:Person .
uni:Xiaoming uni:studiesAt uni:TsinghuaUniversity .
uni:Xiaoming uni:enrolledIn uni:ArtificialIntelligenceCourse .
uni:Xiaoming uni:hasName "小明"@zh .
```

下面逐个解释这段内容涉及的概念。

## 二、名字、地址和普通数据

### 1. 现实事物

现实事物是我们想要描述的对象，可以是具体的，也可以是抽象的。

**例子：** 现实中的小明、清华大学、人工智能课程，都可以成为被描述的事物。

需要注意：现实中的小明本人，不等于计算机中用来表示小明的文字或地址。

### 2. URI

URI 是“统一资源标识符”（Uniform Resource Identifier）。它的作用是给一个事物提供可区分的标识。

**例子：**

```text
https://example.org/university/Xiaoming
```

我们可以约定这个 URI 表示“小明”。它不是小明本人，而是知识系统中用来指代小明的标识。

### 3. IRI

IRI 是“国际化资源标识符”（Internationalized Resource Identifier）。可以把它理解为 URI 的国际化版本，允许使用更广泛的 Unicode 字符。现代 RDF 规范主要使用 IRI 这个术语。

**例子：**

```text
https://example.org/大学/小明
```

为了兼容性和使用方便，实际项目仍经常在 IRI 中使用英文或数字。

> 初学阶段可以暂时把 URI 和 IRI 都理解为“知识图谱中资源的可区分标识”。但“可区分”不等于一个现实对象在全世界只能有一个 IRI：不同系统可能为同一对象创建不同 IRI，确认它们确实表示同一个个体时，可以使用 `owl:sameAs` 建立联系。

### 4. URL

URL 是我们通常所说的网页地址，强调通过某个网络位置找到内容。很多 HTTP/HTTPS URL 同时可以作为 URI 或 IRI 使用。

**例子：**

```text
https://www.w3.org/TR/rdf11-primer/
```

这个 URL 可以在浏览器中打开。相比之下，本体中的 IRI 虽然长得像网址，却不保证一定能打开网页。

### 5. 字面量（Literal）

字面量是字符串、数字、日期、真假值等普通数据。字面量没有自己的 IRI，通常只能放在 RDF 三元组的宾语位置。

**例子：**

```turtle
"小明"
20
"2026-09-01"^^<http://www.w3.org/2001/XMLSchema#date>
true
```

其中，`"小明"`是字符串，`20`是数字，日期带有数据类型，`true`是真假值。

### 6. 语言标签

字符串可以携带语言标签，用来说明文字属于哪种自然语言。

**例子：**

```turtle
"学生"@zh
"Student"@en
```

二者可以作为同一个类的中文和英文名称。

### 7. 空白节点（Blank Node）

空白节点表示“确实存在某个对象，但暂时没有给它全局 IRI”。

**例子：**

```turtle
uni:Xiaoming uni:hasAddress [
    uni:city "北京"@zh
] .
```

方括号中的地址存在，但没有获得类似 `uni:Address001` 的正式名字。初学建模时可以少用空白节点，优先给重要实体分配 IRI。

## 三、RDF：如何把知识写成三元组

### 8. RDF

RDF 是“资源描述框架”（Resource Description Framework）。它是一种知识表示的数据模型，核心思想是把知识写成三元组。

**例子：**

```turtle
uni:Xiaoming uni:studiesAt uni:TsinghuaUniversity .
```

这条 RDF 知识表示“小明就读于清华大学”。

### 9. 三元组（Triple）

一个 RDF 三元组由三个位置组成：

```text
主语　谓词　宾语
```

也可以理解为：

```text
谁/什么　具有怎样的关系　另一个事物或数据
```

**例子：**

```turtle
uni:Xiaoming uni:studiesAt uni:TsinghuaUniversity .
```

- 主语：`uni:Xiaoming`
- 谓词：`uni:studiesAt`
- 宾语：`uni:TsinghuaUniversity`

### 10. 主语（Subject）

主语是当前三元组正在描述的对象。主语可以是 IRI 或空白节点，不能是普通字面量。

**例子：** 在下面的三元组中，`uni:Xiaoming` 是主语。

```turtle
uni:Xiaoming uni:hasName "小明"@zh .
```

### 11. 谓词（Predicate）

谓词表示主语与宾语之间的关系，也叫属性。谓词必须使用 IRI。

**例子：** 在下面的三元组中，`uni:enrolledIn` 是谓词，表示“选修”。

```turtle
uni:Xiaoming uni:enrolledIn uni:ArtificialIntelligenceCourse .
```

### 12. 宾语（Object）

宾语是关系指向的对象或数据，可以是 IRI、空白节点或字面量。

**实体作为宾语的例子：**

```turtle
uni:Xiaoming uni:enrolledIn uni:ArtificialIntelligenceCourse .
```

**字面量作为宾语的例子：**

```turtle
uni:Xiaoming uni:hasName "小明"@zh .
```

### 13. RDF 图（RDF Graph）

许多相互连接的 RDF 三元组组成一张 RDF 图。IRI 表示节点，谓词表示节点之间的有向边，字面量表示数据值。

**例子：**

```text
小明 ──类型──> 学生 ──子类──> 人
 │
 └──选修──> 人工智能课程
```

这几条相互连接的知识共同构成一张小型 RDF 图。

### 14. Turtle

Turtle 是 RDF 的一种文本书写格式。RDF 是数据模型，Turtle 是把这个模型写出来的一种语法，二者不是同一个概念。

**例子：**

```turtle
uni:Xiaoming uni:hasName "小明"@zh .
```

同一份 RDF 数据还可以写成 RDF/XML、JSON-LD 等其他格式。

### 15. 命名空间和前缀（Prefix）

IRI 通常很长。前缀是 IRI 开头部分的缩写，可以让三元组更容易阅读。

**例子：**

```turtle
@prefix uni: <https://example.org/university/> .
```

声明前缀后：

```text
uni:Xiaoming
```

代表完整 IRI：

```text
https://example.org/university/Xiaoming
```

`uni:`只是缩写，不是完整的名字。

### 16. 资源（Resource）

在 RDF 中，任何能够被描述的东西都可以称为资源，包括人、组织、地点、抽象概念、网页等。

**例子：** 小明、学生这个类别、清华大学以及“选修”这种关系，都可以作为 RDF 所描述的资源。

## 四、RDFS：增加类别和层次关系

### 17. RDFS

RDFS 是“RDF Schema”。它在 RDF 的基础上提供了类、子类、子属性、定义域和值域等建模词汇。

**例子：**

```turtle
uni:Student rdfs:subClassOf uni:Person .
```

这表示“每一名学生都是人”。

### 18. 类（Class）

类表示一组具有某种共同特征的个体。可以把类理解为类别或集合。

**例子：**

```turtle
uni:Student rdf:type rdfs:Class .
```

`uni:Student` 表示“所有学生组成的类别”，不是某一名具体学生。

### 19. 个体（Individual）

个体表示领域中的某个具体对象。个体可以属于一个或多个类。

**例子：**

```turtle
uni:Xiaoming rdf:type uni:Student .
```

`uni:Xiaoming` 是一个个体，`uni:Student` 是它所属的类。

### 20. `rdf:type` 和 `a`

`rdf:type` 用来声明某个资源属于哪个类。Turtle 可以用 `a` 作为 `rdf:type` 的简写。

**两种等价写法：**

```turtle
uni:Xiaoming rdf:type uni:Student .
uni:Xiaoming a uni:Student .
```

这里的 `a` 可以读作“是一个”。

### 21. 子类（`rdfs:subClassOf`）

如果类 A 是类 B 的子类，表示“每一个 A 都是 B”。这是类别之间的 `is-a` 关系。

**例子：**

```turtle
uni:Student rdfs:subClassOf uni:Person .
```

由下面两条知识：

```turtle
uni:Xiaoming a uni:Student .
uni:Student rdfs:subClassOf uni:Person .
```

可以推理出：

```turtle
uni:Xiaoming a uni:Person .
```

### 22. 子属性（`rdfs:subPropertyOf`）

子属性表示一种关系比另一种关系更具体。

**例子：**

```turtle
uni:enrolledInRequiredCourse rdfs:subPropertyOf uni:enrolledIn .
```

如果小明“选修必修课程”高等数学，那么也可以推出小明“选修”了高等数学。

### 23. 定义域（Domain）

定义域说明：某属性的主语应该被理解成哪一类事物。在 RDFS/OWL 中，它主要用于推理，不是数据库字段校验。

**例子：**

```turtle
uni:enrolledIn rdfs:domain uni:Student .
uni:Xiaoming uni:enrolledIn uni:ArtificialIntelligenceCourse .
```

推理机可以据此推出：

```turtle
uni:Xiaoming a uni:Student .
```

### 24. 值域（Range）

值域说明：某属性指向的宾语应该被理解成哪一类事物或哪种数据。

**例子：**

```turtle
uni:enrolledIn rdfs:range uni:Course .
uni:Xiaoming uni:enrolledIn uni:ArtificialIntelligenceCourse .
```

推理机可以据此推出：

```turtle
uni:ArtificialIntelligenceCourse a uni:Course .
```

## 五、OWL 和本体

### 25. 本体（Ontology）

在计算机领域，本体是对某个领域的一套形式化知识模型。它通常包含类、属性、逻辑公理以及可选的个体，用于明确领域术语的含义、促进知识共享，并支持计算机处理和推理。

**例子：**“大学本体”可以包含：

- 类：人、学生、教师、课程、大学；
- 属性：就读于、任教于、选修、姓名；
- 公理：学生是人的子类，教师是人的子类；
- 个体：小明、张老师、人工智能课程、清华大学。

本体不是其中某一个类，也不是某一个现实对象，而是这一整套领域知识规范。

常见定义是：

> 本体是对共享概念化的形式化、明确的规范说明。

这句话可以拆成五个部分：

1. **概念化**：从现实领域中抽象出重要事物、类别、关系和规则，形成一个概念模型；它不只是几个概念的清单。
2. **共享**：这套理解被某个项目、组织或领域的参与者共同接受，不只是某个人的私人理解；它不要求全世界所有人都同意。
3. **形式化**：使用 RDF、RDFS、OWL 等具有规定语法和语义的语言表达，使计算机能够解析和处理。
4. **明确**：把类、属性、关系和约束显式声明出来，不能完全依赖人的常识猜测。
5. **规范说明**：把上述约定系统地记录下来；这不表示每一个本体都已经成为国家标准或行业标准。

#### 概念、类、术语和符号

这四者相关，但不是同一个东西：

```text
现实或认识层面的含义：“学生”概念
          ↓ 用 OWL 形式化
本体中的建模结构：Student 类
          ↓ 使用 IRI 标识
本体文件中的符号：uni:Student
          ↓ 添加人类可读名称
中文术语或标签：“学生”
```

对应代码如下：

```turtle
uni:Student a owl:Class ;
            rdfs:label "学生"@zh .
```

表示一类事物的概念通常建模为类，但并非所有概念都建模为类。例如，“就读于”这种关系通常建模为对象属性，具体的小明通常建模为个体，年龄值 `20` 则是字面量。

本体也不只是术语集合。下面只是术语表：

```text
学生、教师、课程、大学
```

本体还要进一步说明这些术语所表示的类、属性及其关系，例如“学生是人的子类”“学生选修课程”，并通过公理赋予它们正式语义。

一个用于表示概念的专业称谓叫作一个**术语**，例如“类”“个体”“公理”。某个领域中许多术语放在一起，才构成**术语集**或**术语体系**。同一个概念可能有多个术语，同一个术语在不同语境中也可能表示不同概念，因此术语、概念和类不能简单画等号。

### 26. OWL

OWL 是“Web 本体语言”（Web Ontology Language）。它建立在 RDF 技术体系上，比 RDFS 能表达更丰富的逻辑关系。

**例子：** 声明“学生和课程是互斥的两个类”：

```turtle
uni:Student owl:disjointWith uni:Course .
```

如果某个个体同时被声明为学生和课程，推理机就可能发现本体不一致。

### 27. 公理（Axiom）

公理是本体明确断言为真的逻辑陈述。子类、等价、互斥、属性特征以及关于个体的类型和属性断言等，都可以是公理。一个简单三元组可能对应一条公理，多个 RDF 三元组也可能共同编码一条复杂的 OWL 公理。

**例子：**

```turtle
uni:Student rdfs:subClassOf uni:Person .
```

这是一个子类公理，含义是“每一个学生都是人”。

### 28. 对象属性（Object Property）

对象属性连接两个个体，也就是“实体到实体”的关系。

**例子：**

```turtle
uni:Xiaoming uni:studiesAt uni:TsinghuaUniversity .
```

`uni:studiesAt` 连接“小明”和“清华大学”两个个体。

### 29. 数据属性（Data Property）

数据属性把个体连接到字符串、数字、日期等字面量。

**例子：**

```turtle
uni:Xiaoming uni:hasAge 20 .
```

`uni:hasAge` 把小明这个个体连接到数字 `20`。

### 30. 注释属性（Annotation Property）

注释属性给类、属性、个体或本体添加方便人阅读的说明，通常不直接参与 OWL 逻辑推理。

**例子：**

```turtle
uni:Student rdfs:label "学生"@zh ;
            rdfs:comment "在教育机构中接受学习的人"@zh .
```

`rdfs:label` 是名称，`rdfs:comment` 是解释。

### 31. 别名

别名通常使用注释属性或自定义数据属性保存。别名字符串只是文字，不是新的本体个体。

**例子：**

```turtle
uni:TsinghuaUniversity uni:hasAlias "清华"@zh ;
                       uni:hasAlias "THU"@en .
```

“清华”和“THU”都是指向同一个大学个体的别名文字。

### 32. `owl:sameAs`

`owl:sameAs` 表示两个 IRI 指向完全相同的个体。两边应该是个体的 IRI，不能用普通字符串代替。

**例子：**

```turtle
uni:TsinghuaUniversity owl:sameAs external:TsinghuaUniversity .
```

这表示两个不同 IRI 指向同一所现实大学。这两个 IRI 可以来自不同知识库，也可以来自同一个知识库；是否来自两个知识库不是使用 `owl:sameAs` 的条件。它不能写成：

```turtle
# 错误示范
uni:TsinghuaUniversity owl:sameAs "清华大学" .
```

### 33. 等价类（`owl:equivalentClass`）

等价类表示两个类拥有完全相同的个体集合。它表达的是逻辑等价，不只是两个中文词意思相近。

**例子：**

```turtle
uni:FacultyMember owl:equivalentClass uni:AcademicStaff .
```

这表示属于其中一个类的所有个体也都属于另一个类。

### 34. 互斥类（`owl:disjointWith`）

互斥类表示两个类不允许拥有共同个体。

**例子：**

```turtle
uni:Person owl:disjointWith uni:Course .
```

这表示同一个对象不能既是人又是课程。

### 35. 属性特征

OWL 可以声明属性具有传递、对称、函数性等逻辑特征。不是所有关系都具有这些特征，必须根据含义谨慎设置。

**对称属性的例子：**

```turtle
uni:classmateOf a owl:SymmetricProperty .
uni:Xiaoming uni:classmateOf uni:Xiaohong .
```

由此可以推出：

```turtle
uni:Xiaohong uni:classmateOf uni:Xiaoming .
```

### 36. 推理机（Reasoner）

推理机是根据本体公理计算隐含知识、检查逻辑一致性的程序。

**例子：** 已知“小明是学生”和“学生是人”，推理机可以自动得出“小明是人”。

### 37. 开放世界假设（Open World Assumption）

OWL 通常采用开放世界假设：没有记录某件事，不代表这件事为假，只代表目前不知道。

**例子：** 本体中没有记录小明的年龄，不能推出“小明没有年龄”，只能说年龄未知。

### 38. TBox

TBox 是本体中描述通用概念结构和规则的部分，主要包含类、属性以及它们之间的公理，可以理解为领域知识的骨架。这里的 TBox 不只是自然语言术语的集合。

**例子：**

```turtle
uni:Student rdfs:subClassOf uni:Person .
uni:enrolledIn rdfs:domain uni:Student ;
               rdfs:range uni:Course .
```

这些语句定义了类别和关系的一般规则。

### 39. ABox

ABox 是关于具体个体的事实断言。

**例子：**

```turtle
uni:Xiaoming a uni:Student ;
              uni:enrolledIn uni:ArtificialIntelligenceCourse .
```

这些语句描述了具体的小明和具体课程。

TBox 和 ABox 合在一起，可以近似理解为“通用规则 + 具体事实”。日常所说的知识库通常同时包含这两部分；OWL 文件也可以同时保存两类内容，因此实际使用中“本体”和“知识库”的边界有时不会被严格区分。

### 40. 本体导入（`owl:imports`）

一个本体可以导入另一个本体，以复用对方的类、属性和公理。

**例子：**大学本体导入通用人物本体：

```turtle
uni:UniversityOntology a owl:Ontology ;
    owl:imports <https://example.org/ontology/person> .

uni:Student rdfs:subClassOf person:Person .
```

这里的 `person:Person` 来自人物本体，`uni:Student` 来自大学本体。一个本体中的类可以成为另一个本体中类的子类。

## 六、最容易混淆的关系

### 类与个体

```text
学生：类
小明：个体
小明是学生：个体属于类
```

```turtle
uni:Xiaoming a uni:Student .
```

### 子类与组成关系

“学生是人”是子类关系：

```turtle
uni:Student rdfs:subClassOf uni:Person .
```

“计算机学院是大学的一部分”是组成关系：

```turtle
uni:ComputerScienceSchool a uni:School ;
                          uni:partOf uni:TsinghuaUniversity .
```

这里的计算机学院和清华大学都是具体个体。不能因为学院是大学的一部分，就说“学院是大学的一种”。如果要描述类层面的普遍组成规则，还需要使用 OWL 类限制等更精确的建模方式。

### 实体关系与文字属性

连接两个实体：

```turtle
uni:Xiaoming uni:studiesAt uni:TsinghuaUniversity .
```

连接实体与文字：

```turtle
uni:Xiaoming uni:hasName "小明"@zh .
```

### IRI 与字面量

```turtle
uni:Xiaoming                    # IRI 的缩写，表示一个实体
"小明"@zh                      # 字面量，只是一段中文文字
```

二者看起来都与“小明”有关，但在 RDF/OWL 中承担完全不同的角色。
